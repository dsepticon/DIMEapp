## Architecture

Each logical location consists of versioned, independently rendered zones. A zone registry owns dimensions, walkable and blocked tiles, background/foreground and lighting palette, deterministic entry points, NPC and terminal layers, node-spawn regions, landmark labels and connection IDs. Only the active zone and its immediate UI metadata are loaded into the renderer. Walking coordinates are client-local; the server persists only zone transitions and meaningful interactions. A zone transition records `from:<source zone>` as the server-issued entry. The destination resolves its matching backlink doorway, inward facing and a collision-safe arrival tile; no browser coordinate is accepted. The explicit generic `arrival` marker is retained for initial and inter-location spawns. Inter-location travel requires a locally available owned ship, a service-zone `assignDeparture` receipt, and the assigned hangar/pad/cockpit zone before `travel` can start. The assignment fixes ship, destination and ROC loading; a different travel payload is rejected. Active ROC retrieval must be stored before assignment. Flight completion updates the authoritative location and arrival zone, then clears the assignment. The general menu can show a route but cannot enable assignment or departure without a local terminal interaction. The server can prove the logical zone and assignment, not every frame of browser movement; local proximity to the terminal is a UI trust boundary, consistent with the documented mining-input limitation.

The room graph has short, reversible connections and explicit exits. ARC-L1 starts with habitation → concourse → transit → refinery/cargo/trade/equipment/departure/hangar; a window corridor and maintenance branch provide exploration without obscuring services. Lyria has outpost, connected surface claims, cave mouth and cave depths, a landing/ASOP bay, raw-gem sale and Mara. Wala now connects Ridge Outpost and South Processing Yard to two surface regions and a cave network. It uses the **same existing DIME gem weights**, as moon-specific rarity is unverified. The additional yards, Lyria mining-supply service, Wala cargo service and geometry are original DIME design choices, not verified Star Citizen geography. Area18 now has fifteen connected districts and rooms: spaceport, assigned hangar, checkpoint, port platform, shuttle, city platform, transit hall, central plaza, habitation row, upper walk, market, retail, service alley, industrial back-service and port cargo lane, with paired return paths. Every spaceport-to-plaza path must pass through both platforms and the shuttle cabin; the port cargo lane is a local service branch, not a transit bypass. These are original functional compositions, not replicas of Star Citizen floor plans.

## Mining and persistence contract

Mining nodes are generated deterministically from a server-owned save-generation seed, stable zone ID, node slot and respawn epoch. The server chooses the mineral from the existing hand/ROC weights, applying a documented zone _eligibility_ filter but never an invented moon rarity table. A coordinate is chosen from collision-safe spawn regions with minimum spacing from other nodes, walls, exits, terminals and unreachable islands. The browser may render a node and submit its stable ID; it cannot choose mineral, yield, price or depletion. A reload or Twitch-channel change preserves the same seed and epoch. The server records sparse exceptions for depleted, fractured and partially collected nodes, rather than storing every default node or each movement frame.

Scanner output reveals a coarse strength and cardinal direction before analysis. A node's visual reveal radius is `4 + 8√(weight/0.5)` tiles, bounded by the existing Hand/ROC spawn weight, so rarer signatures resolve only at closer range. A weaker hint remains available out to 1.5 times that radius; rare nodes can always be found by exploration. The hint never names the mineral. Analyzed node properties are server-derived. The held-laser simulation is local for responsiveness; the server validates node identity, allowable mining class, fracture outcome, elapsed bounds, cargo and quest effects. Browser input cannot be proven cryptographically, so client charge traces are a usability mechanic rather than a trusted source for value or yield.

Charge uses bounded deterministic properties: resistance reduces energy gain, instability adds bounded drift, size and rarity lengthen the required stable duration, tool stats adjust gain/stability. Below optimal, progress decays slowly; within optimal, progress rises; above optimal, overcharge risk rises. Release, pause, focus loss and pointer cancellation stop laser input and cool charge. There is no random unavoidable explosion. Fracture creates server-owned collectible pieces. At all times, node yield equals collected + remaining + explicitly expired/lost units. Each piece has a stable ID and can be collected only once into a capacity-checked Hand or ROC hold. Full storage leaves the piece on the ground. Sparse node and piece state persists across refresh and channels; respawn occurs only after the documented server epoch and never while pieces remain.

Once the required stable hold completes, that progress is latched. This lets a touch player release the laser and press the separate fracture control; a completed hold cannot decay during that handoff. Charge and heat still cool after release. The local browser simulation does not establish trusted physical input, while the server retains authority over the fracture and its yield.

Current formula draft in `shared/miningWorld.ts`: each save generation, zone ID and slot is hashed with FNV-1a, then expanded by a small deterministic PRNG. Six candidates per spawn region (capped at eight per zone) draw from the existing Hand/ROC gem weights. Coordinates are accepted only if flood-fill reachable from the zone spawn, at least 3.5 tiles from another node, and at least 3 tiles from exits, terminals and the zone spawn. Hand size is 1–3 and yield is 0.25–5.00 cSCU; ROC size is 2–5 and yield is 8.00–63.00 cSCU. Fractional hand yields are the owner's explicit Milestone 3 design decision, not a rarity or price change. The authored physical First Shift Dolivine node yields exactly 4 cSCU, split into three collectible pieces. Legacy First Shift records retain their historical whole-cSCU quantities. A depleted node reappears after 30 minutes of server time with the same stable properties; fractured nodes and uncollected pieces do not respawn.

For a node with DIME spawn weight `w`, define rarity difficulty `d = clamp(1−w, 0, 1)`. Required stable seconds are `clamp(1.2 + 0.55·size + 1.4·resistance + 1.3·instability + 0.8·d, 1.5, 8)`. Optimal center is `clamp(0.48 + 0.2·resistance, 0.38, 0.72)`; half-width is `max(0.07, 0.13−0.04·instability+tool optimal-zone assistance)`. Charge uses the tool's power and response, resistance reduction and bounded deterministic instability drift. Below/above optimum, held progress decays at 0.22 seconds per second; inside, it rises one-for-one. Overcharge rises at 0.38/s above its threshold and cools at 0.45/s otherwise. Heat rises at 0.2/s while held and cools at 0.35/s on release. Each update clamps elapsed time to 50 ms to avoid a browser-tab return jump. These are original DIME formulas, not live Star Citizen balance.

All current mineral inventories, cargo holds, mining rewards, refinery orders and node pieces use integer units of 0.01 cSCU. `quantityVersion=2` identifies that interpretation; the absent version identifies a historical whole-cSCU save. The service converts an old save under its revision- and generation-controlled transaction before any new mutation. The compatibility action names keep whole-cSCU request amounts, while new `*Minor` actions accept integer minor units. Old `world.minorRemainders`, where present, fold into the single Hand/ROC inventory representation and are removed by the upgrade. Catalog prices remain aUEC/SCU; BigInt arithmetic produces exact sale numerators, and a bounded signed wallet remainder makes split and combined sales settle identically. Refinery yield, cost and time calculations use integer fixed-point multipliers. Quest counters remain their historical cSCU records and are not rescaled. Each node creates three to six deterministic, non-overlapping, reachable pieces, with larger nodes putting more units in each piece. The tutorial yields 400 units split exactly 125 + 125 + 150. One or two pickups keep the collection objective active. All three yield 4 cSCU raw Dolivine; at the unchanged 1,300 aUEC/cSCU price the sale pays 5,200 aUEC, and the existing 500 aUEC reward produces a 5,700 aUEC wallet from zero. No historical save quantity is reinterpreted as minor units.

ROC retrieval is an owned-vehicle action at a valid ASOP zone. It records one active retrieval checkpoint, never grants ownership, and prevents duplicate retrieval. Vehicle movement remains local; entry, exit, retrieval, storage, inter-location stow and cargo transfer are server-checkpointed. An unreachable active ROC can be recovered only through a designated owned-vehicle service, without copying its cargo.

## Compatibility, reset and release boundary

One HMAC-derived global player save is shared across Twitch channels. Revisions remain monotonic, save generations change only on reset, request receipts remain unique and expiring, and old pending actions cannot mutate a new generation. The canonical server new-player factory must reset zone, entry point, nodes, scanner/mining progression, fractured/ground pieces, active ROC, travel and quest data as well as existing economy and inventory. Legacy missing fields are mapped only by explicit rules and are not silently relocated. Old receipts replay the latest canonical snapshot.

The four gems—Dolivine, Aphorite, Hadanite and Janalite—remain non-refinable in every backend path. First Shift physically begins only at the Lyria outpost and uses raw Dolivine sale and one 500 aUEC completion reward. The ARC-L1 refinery teaches refinable ship ore later. The older route remains compatible where already completed, with the Milestone 2.2 reconciliation policy unchanged.

This gameplay expansion adds location, zone, sparse mining and vehicle checkpoints to the existing global save. It does not require a new Twitch identity practice or a new DynamoDB table/index. Before public release, review the published privacy language for the expanded progression fields and display an unofficial fan-project disclaimer. No privacy page is changed by this branch.
