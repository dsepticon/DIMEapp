# DIME 2D RPG Milestone 1

This branch starts at reviewed commit `39b03db03822ecd509cbf2d00d72b4afb55d03d2`. It does not publish a Twitch ZIP or modify the existing website, Twitch version 0.4.0, AWS, player data, migration code or the privacy page.

## Engine decision

Use a small custom Canvas engine for this first, single-map milestone. [Phaser](https://docs.phaser.io/phaser/concepts/input) provides a larger game framework with built-in [tilemaps](https://docs.phaser.io/phaser-editor/scene-editor/game-objects/tilemap-object); [PixiJS](https://pixijs.com/8.x/guides/concepts/scene-graph) provides a renderer/scene graph and [ticker](https://pixijs.com/8.x/guides/concepts/render-loop), leaving this game's collision and interaction rules to implement. The current scene needs only a 34×22 tile grid, six interactables, a following camera and four-direction movement. Native Canvas and DOM input meet those needs with no new package, remote asset fetch, worker, shader, dynamic code generation or autoplay media. This keeps the Twitch iframe/CSP integration within the existing React/Vite build. Reconsider a library if later milestones require many maps, authored animation pipelines or complex physics; do not extend this small engine into an unreviewable framework.

The Canvas has a fixed 320×208 logical resolution, scaled with CSS and pixelated interpolation. The drawing loop and movement state stay outside React; React rerenders only when the nearby prompt or server/UI state changes. The engine attaches keyboard/focus/visibility listeners once and removes them with its animation frame on unmount. React Strict Mode remounts the component safely. Four touch directions use pointer capture and `touch-action: none`; on narrow panels, the large touch controls overlay the lower corners of the map to remain visible within a 500px viewport. Escape closes dialogue. Window blur and hidden visibility clear held movement. Reduced-motion preference freezes decorative walking animation. No sound is used.

The map is an original programmatic outpost and mine: solid perimeter/building/shaft walls, a two-tile mine entrance, three mineral seams, refinery and market terminals, and a ship/travel terminal. “Dolivine,” “Aphorite” and “Hadanite” are labels from DIME's existing resource catalog, not guaranteed rewards. The server chooses any hand-mining reward. Walking and camera position are local and discarded when leaving the tab. Away from Lyria, the scene is explicitly marked as a preview and deposits cannot submit. A deposit at Lyria sends one existing `mine` action through the action adapter and `useGame`, which retains revision, retry and idempotency behavior. Current pending actions or unavailable Twitch authorization block another submission. Extraction completion, balances and inventory remain server-owned. Refinery/Market terminals open the existing React tabs; the travel terminal opens the existing claim selector below the map. The previous mining controls remain in a collapsed section for all existing modes. Moving the existing travel strip below the Mining scene keeps the map and controls higher in the 318×500 Panel viewport; other tabs retain the strip above their content.

The 34×22 world, original terminal/mineral art, collision, three server-backed seams, mine entrance and local walking remain. The display letterboxes horizontally in the 1024×768 preview rather than stretching pixels.

The permanent header, wallet strip, navigation tabs, title and instructions are gone from ordinary play. Wallet and cargo capacity sit in a small top-corner HUD, with a compact menu button and unobtrusive connection message. A short DIME title scene transitions to a temporary Lyria area card. The D-pad and Interact button occupy translucent bottom corners and disappear while a menu is open. Cargo is the backpack overlay; Profile is character status. Refinery, Market and Travel open from their corresponding terminals or the pause menu. Classic mining controls remain available through the pause menu. Overlays dim/pause the map, scroll internally, close with Escape or the visible button, and resume movement without held-key leakage. Connection and retry problems use a game-styled modal. No backend, global-save, action, schema, package, Twitch asset or AWS change is part of this milestone.

## Milestone 1.2: authored art and game-native windows

The small custom Canvas engine remains dependency-free. `palette.ts` defines the limited steel, cyan, amber, rock and mineral palette and its art grid: 16×16 world tiles, 16×22 miner/worker sprites, 16×16 inventory icons and a four-pixel UI spacing base. CSS uses matching colour tokens. World art uses integer Canvas coordinates and disables interpolation; the 160-pixel logical width shows ten world tiles across the 318px Panel, and the larger preview is letterboxed. No third-party art, font, sound, tracker or runtime asset was added.

`mapData.ts` owns the 34×22 tile topology, scenery, interaction positions and area names. `world.ts` owns collision and local movement. `sprites.ts` draws the original helmet, visor, suit, life-support pack, boots and mining tool in four directions with three walking frames, idle lamp motion and a brief tool motion. `renderWorld.ts` layers authored floor variation, wall faces, survey marks, shadowed crates/racks/cabinets, machinery, haul rail, mine supports, lamps, mineral formations, terminals and station worker. The outpost has a ship pad, staging lane, refinery corner, market counter and striped mine threshold; the mine uses dark rock, rail and blocked side passages. Scenery collision matches each blocked prop. The entrance changes only local area state and briefly fades/locks input; it makes no backend write. The worker has a short greeting and no quest logic.

React still owns Twitch connection, authoritative state, notices and action submission. The Canvas loop owns drawing, camera, keyboard/touch movement, collision and map fade, and removes its observers/listeners/animation frame on unmount. The `RpgPanel` bridges a nearby object to a React overlay or to the existing guarded mining action adapter. Walking, dialogue, animation and map transitions send no API calls. Deposit, cargo, purchase, sale, refinery and travel actions retain the existing server contract, revisions and idempotent retry path. No save schema, player identity, backend route or deployment changed.

The primary Cargo, Market, Refinery, Travel and Profile windows share one pixel-border and icon language and contain no native select or number controls. Cargo has Hand/ship tabs, ore cards, selected material detail, capacity bars and stepper transfer controls. Market has Buy/Sell views, a bounded scrollable supply catalog, prices, quantities and server-result text. Refinery has recipe cards, method selection, quote, cost, duration and collection queue. Travel presents location nodes, disabled future routes, ship status and a separate confirmation step. Profile has a Canvas portrait, equipment slots, fleet and save status without a raw Twitch identifier. The pause menu provides access to these windows, controls, connection status, privacy policy and secondary classic mining operations. Terminal introductions, NPC greeting and action feedback use one dialogue window; text advances progressively, while reduced-motion and critical text show immediately. Escape and visible controls close windows, and movement resumes without a held-key carryover.

The 318×500 Panel and 360×640 Mobile keep the whole ordinary viewport as the game surface, without document scrolling; the 1024×768 preview retains the handheld-width composition. The D-pad, Interact and HUD remain readable without obscuring the miner. In-game windows scroll internally when content exceeds the Panel height. Visual review files under ignored `test-results/` are `m1-2-panel-*.png` and `m1-2-mobile-*.png` for outpost, mine, interaction prompt, NPC dialogue, Cargo, Market, Refinery, Travel, Profile and pause menu, plus `m1-2-preview-1024x768.png`. These local screenshots are review artifacts, not Twitch assets.
